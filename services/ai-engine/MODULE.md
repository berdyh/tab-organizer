# AI Engine Module Card

- purpose: AI runtime for embeddings, provider switching, clustering, RAG, indexing, and chat/search APIs.
- product/module functionality: provider health/config, generation, embeddings, LanceDB persistence, chunked document indexing/search, cluster labeling.
- scope boundaries: owns AI behavior and vector data; does not own backend session persistence, scraping internals, or Streamlit state.
- connected modules/submodules: Backend Core, Browser Engine, Shared Config, Ops Tooling host-AI mode, Test Harness.
- allowed change types: provider adapter updates, auth/config hardening, RAG/clustering fixes, route split/refactor, focused tests.
- special operating rules: preserve bearer auth, `AI_ENGINE_ALLOW_UNAUTHENTICATED` fail-closed default, provider-state locking, embedding dimension checks, and local CLI guardrails. Structured logging goes through shared `services/observability.py`: `RequestIDMiddleware` binds/echoes `X-Request-ID`; log provider switches, index counts, and cluster failures via `log_event`. The Dockerfile now copies `services/__init__.py` + `services/observability.py` (previously it copied only `app/` and `config/`) — keep that in sync when the shared module changes. Never log tokens, credentials, or document bodies (counts/lengths only). `app/main.py`'s `lifespan` calls `config.config_loader.get_ai_config().validate_config()` and refuses to start on a malformed catalog (finding 27); it then checks `llm_client.get_runtime_health()` and, if the selected LLM/embedding provider is unusable (e.g. missing API key, unreachable/missing-model Ollama), logs a structured `provider.unusable_at_startup` event and lets the service start anyway — degraded-visible beats dead (WI0 B1). `GET /health` reports `{"status": "degraded", "runtime": {...reason per capability...}}` in that case; never collapse it to a bare boolean. Browser origins are an allowlist, never `*`: `app/main.py` resolves `allow_origins` through shared `services/cors.py` (`CORS_ALLOWED_ORIGINS`, default the Web UI on :8089) and sets `allow_credentials=False`. Web UI calls this service server-side with `requests`, so it has no legitimate browser-side caller; the old `allow_origins=["*"]` + `allow_credentials=True` let any page the user had open read its responses. The Dockerfile copies `services/cors.py` — keep that in sync. Frozen by `tests/security/test_cors_policy.py` (SEC-43). **No provider is ever selected implicitly** (`routing.silent_fallback: false` in `config/ai_models.yaml`; `docs/SPEC-provider-routing.md` R1-R4): `AI_PROVIDER`/`EMBEDDING_PROVIDER` have no defaults anywhere — not in `llm_client.py`, not in `docker-compose.yml`, not in `.env.example` — and the embedding path no longer swaps in a capable provider when the chosen one cannot embed. Unset or incapable raises `ProviderSelectionError` (`{code, cause, fix}`, sibling of browser-engine's `CDPConnectionError`), which `LLMClient.__init__` *stores* rather than raises so the service still starts and reports `degraded`; the request paths then fail closed. The list of embedding-capable providers in that error is derived from the catalog via `is_provider_supported(p, "embeddings")` — never hardcode it. That fail-closed contract covers the whole *class* of misconfiguration, not the provider field alone: any exception raised while resolving a role (typo'd `LLM_MODEL`/`EMBEDDING_MODEL`, non-integer or catalog-contradicting `EMBEDDING_DIMENSIONS`, anything unforeseen) is converted by `_resolve_role` into a structured error and degrades — `main.py` builds `LLMClient()` at module scope, so a raise there blackholes the service at import. Embedding **dimensions come from the catalog only**: a missing `dimensions` entry and a mismatched `EMBEDDING_DIMENSIONS` both fail closed (`embedding_dimensions_unknown` / `_mismatch`); the old `model_config.get("dimensions", 1536)` invented a width and announced it. A model marked `dimensions_configurable` in the catalog is the one exception, and it does not weaken the invariant: such a model is *told* what width to emit, so an override below its native width is the request rather than drift (above it, `embedding_dimensions_out_of_range`). `EmbeddingConfig.dimensions_configurable` carries the flag and `OpenAIEmbeddingProvider.embed` MUST put `dimensions` on the wire for it -- drop that and the announced width and the real one diverge silently, which is exactly the class this check exists to catch. **A provider's `supports.embeddings` flag is set by CALLING its embedding endpoint, never by reading a model listing**: openrouter was wrongly recorded as embedding-incapable for a day on the strength of a scan of its chat-only `/v1/models` listing, which took the `openrouter -> OpenAIEmbeddingProvider` adapter entry down with it as "unreachable" (it is reachable, and `/v1/embeddings` is OpenAI-compatible). `test_embedding_capability_flag_agrees_with_the_adapter_map` now fails the build whenever the catalog flag and the adapter map disagree. A **selection or availability failure is never absorbed**: `_ensure_current_provider_ready` raises `ProviderUnavailableError` (a `ProviderSelectionError` subclass) so best-effort `except Exception` handlers can re-raise both with one guard; `TabClusterer.generate_cluster_label` does exactly that, and only genuine per-cluster provider failures fall through to a placeholder — counted, `log_event`-logged, and surfaced as `label_failures` plus a per-cluster `label_error` in the `/cluster` response. The active provider is announced on every surface: a `provider.active` log line per role at startup and a top-level `providers` block on `GET /health` (beside `runtime`, not inside it — `runtime` is diagnostics, `providers` is the stable attribution contract the TS facade will read). `/health` is unauthenticated, so nothing in either surface may carry a key or token — including **URL userinfo**: every `reason`/`server_url` goes through `redact_url_userinfo()`, because `OLLAMA_HOST=http://user:pass@host` otherwise served the credential verbatim. `GET /providers` is authenticated like every other non-`/health` endpoint (it discloses `api_key_configured` per provider and the whole catalog); frozen by `tests/security/test_token_scopes.py`'s `AI_PROTECTED`. The catalog is read as PROVIDER ROUTES: a model entry's key is its wire id, `provider` names the one provider serving it, `model_family` links routes to the same weights, and `cost_model` is resolved from the provider (`config/MODULE.md`). `dimensions` must always be read from the ROUTE's own entry and never hoisted onto the family — two routes to one family can emit different widths, and an announced width that differs from the emitted one makes ai-engine refuse every write to its own table (`test_two_routes_to_one_family_keep_their_own_vector_widths`). `gemini_cli` joins `claude_code`/`codex_cli`/`codex_acp` as a subscription LLM-only provider in `PROVIDERS`, `CLI_PROVIDER_COMMANDS`, `_create_llm_provider` and `_cli_provider_available`; `LLMClient.PROVIDERS` is a *mirror* of the catalog, not a second source of truth — a test asserts every provider and capability agrees with `ai_models.yaml`. Frozen by `tests/unit/test_provider_routing.py`. **LanceDB is pinned in two places and they must move together**: `services/ai-engine/requirements.txt` (what ships) and `tests/requirements.txt` (what `tests/unit/test_rag_lancedb_persistence.py` drives — that suite uses a *real* LanceDB, not a mock, so a split pin means the tests validate a version the image does not contain). The pin is `lancedb==0.6.13` / `pylance==0.10.12`, held to the 0.6 line deliberately: 0.8+ crosses a pyarrow floor bump and an async API rewrite, and `rag.py` depends on the 0.6-era surface (`create_table(data=<arrow table>)` with a `fixed_size_list` vector column, `table.to_pandas()`, the no-arg `table.search()` empty-query builder used by `summarize_session`, and `count_rows(filter=...)`). The previous pin `0.6.8` was a real, working release that upstream **deleted** from PyPI — all of 0.6.6–0.6.12 vanished, the only multi-version hole in the project's history — which silently made the image unbuildable for months while cached images kept working. When bumping, verify against a table written by the *old* version, not just a fresh one: the on-disk format is the thing a version bump can break quietly, and prefer moving forward (newer reader over older data) rather than back.

The embeddings branch guards exactly this case with an explicit `embedding_model_not_selected` raise; the llm branch has no equivalent. Left unfixed on purpose — closing it makes a switch that half-succeeds today start failing closed, which is a behaviour decision, not a typing one.
