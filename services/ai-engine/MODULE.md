# AI Engine Module Card

- purpose: AI runtime for embeddings, provider switching, clustering, RAG, indexing, and chat/search APIs.
- product/module functionality: provider health/config, generation, embeddings, LanceDB persistence, chunked document indexing/search, cluster labeling.
- scope boundaries: owns AI behavior and vector data; does not own backend session persistence, scraping internals, or Streamlit state.
- connected modules/submodules: Backend Core, Browser Engine, Shared Config, Ops Tooling host-AI mode, Test Harness.
- allowed change types: provider adapter updates, auth/config hardening, RAG/clustering fixes, route split/refactor, focused tests.
- special operating rules: preserve bearer auth, `AI_ENGINE_ALLOW_UNAUTHENTICATED` fail-closed default, provider-state locking, embedding dimension checks, and local CLI guardrails. Structured logging goes through shared `services/observability.py`: `RequestIDMiddleware` binds/echoes `X-Request-ID`; log provider switches, index counts, and cluster failures via `log_event`. The Dockerfile now copies `services/__init__.py` + `services/observability.py` (previously it copied only `app/` and `config/`) — keep that in sync when the shared module changes. Never log tokens, credentials, or document bodies (counts/lengths only). `app/main.py`'s `lifespan` calls `config.config_loader.get_ai_config().validate_config()` and refuses to start on a malformed catalog (finding 27); it then checks `llm_client.get_runtime_health()` and, if the selected LLM/embedding provider is unusable (e.g. missing API key, unreachable/missing-model Ollama), logs a structured `provider.unusable_at_startup` event and lets the service start anyway — degraded-visible beats dead (WI0 B1). `GET /health` reports `{"status": "degraded", "runtime": {...reason per capability...}}` in that case; never collapse it to a bare boolean. Browser origins are an allowlist, never `*`: `app/main.py` resolves `allow_origins` through shared `services/cors.py` (`CORS_ALLOWED_ORIGINS`, default the Web UI on :8089) and sets `allow_credentials=False`. Web UI calls this service server-side with `requests`, so it has no legitimate browser-side caller; the old `allow_origins=["*"]` + `allow_credentials=True` let any page the user had open read its responses. The Dockerfile copies `services/cors.py` — keep that in sync. Frozen by `tests/security/test_cors_policy.py` (SEC-43). **No provider is ever selected implicitly** (`routing.silent_fallback: false` in `config/ai_models.yaml`; `docs/SPEC-provider-routing.md` R1-R4): `AI_PROVIDER`/`EMBEDDING_PROVIDER` have no defaults anywhere — not in `llm_client.py`, not in `docker-compose.yml`, not in `.env.example` — and the embedding path no longer swaps in a capable provider when the chosen one cannot embed. Unset or incapable raises `ProviderSelectionError` (`{code, cause, fix}`, sibling of browser-engine's `CDPConnectionError`), which `LLMClient.__init__` *stores* rather than raises so the service still starts and reports `degraded`; the request paths then fail closed. The list of embedding-capable providers in that error is derived from the catalog via `is_provider_supported(p, "embeddings")` — never hardcode it. That fail-closed contract covers the whole *class* of misconfiguration, not the provider field alone: any exception raised while resolving a role (typo'd `LLM_MODEL`/`EMBEDDING_MODEL`, non-integer or catalog-contradicting `EMBEDDING_DIMENSIONS`, anything unforeseen) is converted by `_resolve_role` into a structured error and degrades — `main.py` builds `LLMClient()` at module scope, so a raise there blackholes the service at import. Embedding **dimensions come from the catalog only**: a missing `dimensions` entry and a mismatched `EMBEDDING_DIMENSIONS` both fail closed (`embedding_dimensions_unknown` / `_mismatch`); the old `model_config.get("dimensions", 1536)` invented a width and announced it. A **selection or availability failure is never absorbed**: `_ensure_current_provider_ready` raises `ProviderUnavailableError` (a `ProviderSelectionError` subclass) so best-effort `except Exception` handlers can re-raise both with one guard; `TabClusterer.generate_cluster_label` does exactly that, and only genuine per-cluster provider failures fall through to a placeholder — counted, `log_event`-logged, and surfaced as `label_failures` plus a per-cluster `label_error` in the `/cluster` response. The active provider is announced on every surface: a `provider.active` log line per role at startup and a top-level `providers` block on `GET /health` (beside `runtime`, not inside it — `runtime` is diagnostics, `providers` is the stable attribution contract the TS facade will read). `/health` is unauthenticated, so nothing in either surface may carry a key or token — including **URL userinfo**: every `reason`/`server_url` goes through `redact_url_userinfo()`, because `OLLAMA_HOST=http://user:pass@host` otherwise served the credential verbatim. `GET /providers` is authenticated like every other non-`/health` endpoint (it discloses `api_key_configured` per provider and the whole catalog); frozen by `tests/security/test_token_scopes.py`'s `AI_PROTECTED`. `LLMClient.PROVIDERS` is a *mirror* of the catalog, not a second source of truth — a test asserts every provider and capability agrees with `ai_models.yaml`. Frozen by `tests/unit/test_provider_routing.py`.
- current stubs/placeholders: the R4 UI badge and R5 per-response attribution are deliberately unbuilt here (TS facade / wk10 cutover) — do not add provider columns to the Python store for them. The former stub "unavailable local subscription CLI providers should report unhealthy rather than silently falling back" is **done**, not dropped: an unavailable selected provider now raises `ProviderUnavailableError` from every request path and reports `degraded` on `/health`. Still open: `switch_provider`'s own `is_provider_supported(..., "embeddings")` guard is shadowed by `get_provider_runtime_state()`, which repeats the check and raises the identical message — no test can distinguish the guard's presence, so it is untestable defence-in-depth; the *behaviour* (a refused switch substitutes nothing) is what is frozen.
- irrelevant or incomplete code to remove/rework: `app/main.py` is a broad route/runtime file and should be split behind compatible routers.
- docs that must stay aligned: `docs/AI_CONFIG.md`, `docs/SPEC-provider-routing.md`, `docs/ARCHITECTURE_PLAN.md`, `README.md`, provider and RAG submodule cards.
- local validation commands/checks: `make test-ai`; focused files `tests/unit/test_rag_lancedb_persistence.py`, `tests/unit/test_startup_config_validation.py`, `tests/unit/test_provider_routing.py`; `make test-security` when touching an endpoint's auth; then integration smoke for `/health`, `/providers`, indexing, and chat/search changes.
