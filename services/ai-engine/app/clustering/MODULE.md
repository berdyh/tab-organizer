# AI Clustering Submodule Card

- purpose: cluster scraped tabs and generate labels/summaries.
- product/module functionality: embeddings grouping, dimensionality reduction, HDBSCAN clusters, LLM-generated cluster labels.
- scope boundaries: owns clustering pipeline only; URL/session state lives in Backend Core.
- connected modules/submodules: AI Core, Backend clustering proxy, Web UI clustering page.
- allowed change types: clustering algorithm fixes, label prompt safety, model-dimension handling, tests.
- special operating rules: tab content in prompts must be marked untrusted; recursive sub-clustering is bounded by `max_subcluster_depth` plus a no-progress guard (a single child equal to its parent stops recursion); UMAP params must keep `n_components + 1 < n_samples` and below `min_cluster_corpus` clustering is skipped for a single "All Tabs" cluster so small corpora never 500. **The `ImportError` fallbacks must stay LOUD and the backend must stay observable.** `reduce_dimensions` and `cluster_embeddings` fall back to SVD and `_kmeans_cluster` when umap/hdbscan are missing; until 2026-08-07 they did so silently, and `tests/requirements.txt` shipped neither library, so every clustering test in CI characterised the fallback while naming UMAP+HDBSCAN (plan decision 48). The fallback is not equivalent: `_kmeans_cluster` caps at 10 clusters at ANY corpus size and never emits a `-1` noise label, so "how many groups" and "which tabs are outliers" both change. `last_reduce_backend`/`last_cluster_backend` record what actually ran; any test or evaluation reporting geometry results must assert them. Both libraries are now pinned in `tests/requirements.txt` alongside `scikit-learn==1.4.0` — that third pin is load-bearing, not transitive: umap-learn 0.5.5 calls `check_array(force_all_finite=)`, renamed in scikit-learn 1.6, so an unpinned resolve breaks UMAP outright.
- **Label attribution (spec R5).** A generated label carries `generated_by: {provider, model, prompt_version, run_at}` in `to_dict`, stamped per CLUSTER because backend persists only the `clusters` array. Absent — never null-filled — when nothing generated the name, so an "Uncategorized" noise row or a failed label cannot read as model output. Bump `LABEL_PROMPT_VERSION` when the label prompt changes in a way that could move the labels.
- current stubs/placeholders: small-sample behavior is covered and should remain explicit. **The G4 evaluation gating plan decision 25** (keep or drop the Python UMAP/HDBSCAN sidecar at the TS migration) runs from `scripts/eval/`; its pre-registered decision rule is the 2026-08-07 addendum in `docs/ARCHITECTURE_PLAN.md` and the verdict lands in `docs/EVAL-clustering.md`.
- irrelevant or incomplete code to remove/rework: `cluster_sync` has no production caller (only `tests/unit/test_clustering.py`); `/cluster` uses the async `cluster()`. Left in place pending the G4 verdict, which may retire this module wholesale.
- docs that must stay aligned: AI Engine card and README clustering feature text.
- local validation commands/checks: `make test-ai`; focused file `tests/unit/test_clustering.py`.
