# Web UI Service

A [Streamlit](https://streamlit.io/) front end for Tab Organizer. Nearly everything
goes through `backend-core` — sessions, URLs, scraping orchestration, export, and
also **clustering, chat, search and the auth flow**, which this file used to
attribute to `ai-engine` and `browser-engine`. They moved behind backend-core
(WI0 B7 and the wk0 ops pass) because Backend Core is the only orchestrator.

What is left going direct: `ai-engine` for `/summarize`, `/providers`,
`/providers/switch` and `/config`; `browser-engine` for a tokenless `/health`
probe and nothing else. `search()` calling ai-engine directly is a known
remaining gap, recorded on [MODULE.md](MODULE.md).

> Parent docs live in the repo root. See [../../README.md](../../README.md) and
> [../../docs/ARCHITECTURE_PLAN.md](../../docs/ARCHITECTURE_PLAN.md) for the wider
> context.
> The local development boundary is captured in [MODULE.md](MODULE.md).

## Layout

```
services/web-ui/
├── app.py              # Streamlit entry point + sidebar navigation
├── Dockerfile          # Production image (Python 3.12 + Streamlit)
├── requirements.txt
├── scripts/            # Local helper scripts
│   ├── run_single_test.sh
│   └── test_quick.sh
└── src/
    ├── api/
    │   └── client.py   # Thin HTTP client used by every page
    └── pages/
        ├── url_input.py
        ├── scraping.py
        ├── clustering.py
        ├── chatbot.py
        ├── platform.py
        └── settings.py
```

Pages are plain Python modules that Streamlit re-runs top-to-bottom on every
interaction. Cross-service calls go through `src/api/client.py`, which reads the
service URLs from environment variables.

## Running locally

In Docker (recommended — matches CI):

```bash
./scripts/cli.py start -d           # full stack
# UI: http://localhost:8089
```

Or directly with Streamlit (requires the other services running somewhere):

```bash
cd services/web-ui
uv pip install -r requirements.txt
streamlit run app.py --server.port=8089 --server.address=0.0.0.0
```

## Configuration

The UI reads these environment variables:

| Variable | Default in `docker-compose.yml` | Purpose |
|----------|---------------------------------|---------|
| `BACKEND_URL` | `http://backend-core:8080` | Sessions, URLs, scraping, export, clustering, chat, search, auth flow |
| `AI_ENGINE_URL` | `http://ai-engine:8090` | `/summarize`, `/providers`, `/providers/switch`, `/config` only |
| `BROWSER_ENGINE_URL` | `http://browser-engine:8083` | A tokenless `/health` probe only |
| `AI_ENGINE_API_TOKEN` | generated by the CLI | Bearer auth for the AI Engine calls above |
| `BACKEND_AGENT_API_TOKEN` | generated by the CLI | Bearer auth for the three backend routes that require the agent scope (`/chat`, `/auth/pending`, `/auth/credentials`). Without it those three flows 401 |
| `UI_API_TIMEOUT` | `30` | Seconds before an outbound API call gives up |

When running outside Docker, point them at `http://localhost:<port>` instead.

## Testing

The repo's unified test pipeline covers the UI:

```bash
make test-web                            # focused Web UI unit checks
./scripts/cli.py test --type unit        # full unit suite
./scripts/cli.py test --type integration # against running services
./scripts/cli.py test --type e2e         # full stack
```

Helper scripts under `services/web-ui/scripts/` wrap common loops while
iterating locally:

```bash
./scripts/test_quick.sh                         # focused Web UI pytest target
./scripts/run_single_test.sh tests/unit/... -q  # run selected pytest args
```

## Adding a new page

1. Create `src/pages/my_page.py` exposing a `render()` function.
2. Import and add it to the sidebar selector in `app.py`.
3. Use `src/api/client.py` for any backend call rather than `requests` directly,
   so error handling and base URLs stay consistent.
