# Browser Engine Module Card

- purpose: scrape public/authenticated pages and attach to local browser tabs for import/open workflows.
- product/module functionality: scrape API, CDP tab import/open API, auth detection, auth queue, HTTP/browser scraping, backend callbacks, AI indexing handoff.
- scope boundaries: owns scraping and extraction runtime; does not own backend persistence or AI indexing internals.
- connected modules/submodules: Backend Core callbacks and tab APIs, AI Engine indexing, Web UI scraping page, Ops CLI/MCP tools, Test Harness.
- allowed change types: scraper lifecycle fixes, auth detection, callback/error contract work, route split/refactor, tests.
- special operating rules: preserve bearer auth on control/auth endpoints, local-only CDP attach, default rejection of private/local scrape targets, batch-local scraper instances, browser launch lock, Playwright shutdown in `finally`, callback token headers, and downstream error reporting. `validate_cdp_url` keeps the local-host allowlist for CDP *input*, but Chrome's debug port rejects any Host header that is not an IP/`localhost`, so `resolve_cdp_connect_url` resolves the input host (notably `host.docker.internal`) to its IP before Playwright connects; connect failures raise `CDPConnectionError` with an actionable `{code, cause, fix}` message (WI0 B2). Downstream `*_failed` counters track per-document consequence: a failed batched `/index` call increments `ai_index_failed` by the document count and tags the error `scope="batch"` + `docs_in_failed_call` (WI0 B5). Structured logging goes through shared `services/observability.py`: `RequestIDMiddleware` binds/echoes `X-Request-ID`; the detached `scrape_urls_background` task receives the request id explicitly and must forward it on the backend callback and AI index calls (merged after the auth headers). Log per-callback failures, index dispatch counts, and auth-queue transitions via `log_event`, never credentials or page bodies (domains/lengths only). `app/main.py`'s `lifespan` calls `config.config_loader.get_ai_config().validate_config()` and refuses to start on a malformed catalog (finding 27) — Browser Engine does not otherwise read this config, but ships and validates the same file AI Engine depends on; `Dockerfile`/`requirements.txt` now copy `config/` and pin `PyYAML` to support this.
- current stubs/placeholders: callback failures are best-effort and must remain visible in batch status; private-network scraping is an explicit local opt-in via `SCRAPE_ALLOW_PRIVATE_NETWORKS`; managed browser launch/profile lifecycle is deferred; CDP attach from a container needs Chrome listening on a Docker-reachable interface (default 127.0.0.1 bind is unreachable) — an interim host-side `socat` bridge is documented in `docs/MANUAL_SETUP.md`, and host-side tab capture (TS migration, plan decision 24) is the durable replacement.
- irrelevant or incomplete code to remove/rework: `app/main.py` mixes routes, background task state, callbacks, and downstream accounting; split behind compatible routes later.
- docs that must stay aligned: `docs/SCRAPER_AGENTIC_ANALYSIS.md`, `docs/ARCHITECTURE.md`, `docs/TESTING.md`.
- local validation commands/checks: `make test-browser`; focused files `tests/unit/test_browser_tab_harvester.py`, `tests/unit/test_startup_config_validation.py`; integration smoke for `/scrape/single` and callback status changes.
