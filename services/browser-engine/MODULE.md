# Browser Engine Module Card

- purpose: scrape public/authenticated pages and attach to local browser tabs for import/open workflows.
- product/module functionality: scrape API, CDP tab import/open API, auth detection, auth queue, HTTP/browser scraping, per-result delivery to the backend ingest endpoint.
- scope boundaries: owns scraping and extraction runtime; does not own backend persistence or AI indexing internals. Browser-engine NEVER writes vectors — it POSTs each result to backend `POST /api/v1/ingest/v1` and backend-core is the sole ai-engine `/index` writer.
- connected modules/submodules: Backend Core ingest/callback + tab APIs, Web UI scraping page, Ops CLI/MCP tools, Test Harness.
- allowed change types: scraper lifecycle fixes, auth detection, callback/error contract work, route split/refactor, tests.
- special operating rules: preserve bearer auth on control/auth endpoints, local-only CDP attach, default rejection of private/local scrape targets, batch-local scraper instances, browser launch lock, Playwright shutdown in `finally`, callback token headers, and downstream error reporting. `validate_cdp_url` keeps the local-host allowlist for CDP *input*, but Chrome's debug port rejects any Host header that is not an IP/`localhost`, so `resolve_cdp_connect_url` resolves the input host (notably `host.docker.internal`) to its IP before Playwright connects; connect failures raise `CDPConnectionError` with an actionable `{code, cause, fix}` message (WI0 B2). Each scrape result is delivered to backend `POST /api/v1/ingest/v1` with a fresh `capture_id` (uuid4 per fetch attempt), a per-`(session,url)` in-process `attempt` counter (`_next_ingest_attempt`; resets to 1 across restarts by design — backend keys ordering on `(fetched_at, attempt)`), `fetched_at` (result.scraped_at ISO), and `auth_used`. A 200-`ignored` (duplicate/stale) is a SUCCESSFUL delivery, not a failure — only transport/4xx/5xx errors increment `backend_callback_failed` (one document per ingest, so `_record_downstream_error` no longer carries batch `docs_affected`/`scope`). AI-index failures now live in the backend ledger and surface via backend `/scrape/status`, not here; browser-engine emits no `ai_index` errors. Structured logging goes through shared `services/observability.py`: `RequestIDMiddleware` binds/echoes `X-Request-ID`; the detached `scrape_urls_background` task receives the request id explicitly and must forward it on the ingest call (merged after the auth headers). Log per-callback failures and auth-queue transitions via `log_event`, never credentials or page bodies (domains/lengths only). `app/main.py`'s `lifespan` calls `config.config_loader.get_ai_config().validate_config()` and refuses to start on a malformed catalog (finding 27) — Browser Engine does not otherwise read this config, but ships and validates the same file AI Engine depends on; `Dockerfile`/`requirements.txt` now copy `config/` and pin `PyYAML` to support this.
- current stubs/placeholders: callback failures are best-effort and must remain visible in batch status; private-network scraping is an explicit local opt-in via `SCRAPE_ALLOW_PRIVATE_NETWORKS`; managed browser launch/profile lifecycle is deferred; CDP attach from a container needs Chrome's debug port bridged to the Docker bridge interface (the default 127.0.0.1 bind is unreachable, and headed Chrome ignores `--remote-debugging-address` so it stays on loopback) — the interim path is a host-side `socat TCP-LISTEN:9222,fork,bind=172.17.0.1 TCP:127.0.0.1:9222` bridge (172.17.0.1 is the default docker0 bridge IP; confirm yours with `docker network inspect bridge`, and do NOT bind `0.0.0.0`, which LAN-exposes the unauthenticated debug port), documented in `docs/archive/2026-07-24-MANUAL_SETUP.md`; host-side tab capture (TS migration, plan decision 24) is the durable replacement.
- irrelevant or incomplete code to remove/rework: `app/main.py` mixes routes, background task state, callbacks, and downstream accounting; split behind compatible routes later.
- docs that must stay aligned: `docs/archive/2026-07-24-SCRAPER_AGENTIC_ANALYSIS.md`, `docs/ARCHITECTURE_PLAN.md`, `docs/TESTING.md`.
- local validation commands/checks: `make test-browser`; focused files `tests/unit/test_browser_tab_harvester.py`, `tests/unit/test_startup_config_validation.py`; integration smoke for `/scrape/single` and callback status changes.
