# Backend Sessions Submodule Card

- purpose: session lifecycle and persisted tab-processing state.
- product/module functionality: create/list/delete sessions, current session state, URL records, tab import job records, SQLite FTS search rows, clusters, callback metadata, the idempotent ingest ledger (`ingest_captures`).
- scope boundaries: owns backend session data model and keyword search metadata; URL normalization belongs in `url_input`, semantic vectors and chunked content belong in AI Engine.
- connected modules/submodules: Backend API (ingest endpoint), URL input, Browser callbacks, export, Test Harness persistence tests.
- allowed change types: persistence fixes, migration-safe schema additions, status bookkeeping, focused tests.
- special operating rules: keep file-backed SQLite behavior and in-memory fallback behavior equivalent where tests require it (asserted by `tests/unit/test_ingest_v1.py::test_in_memory_and_sqlite_parity`); keep FTS queries parameterized. `ingest_scrape_result(IngestCapture) -> IngestOutcome` is the single idempotent writer, entirely under the `RLock`: (1) known `capture_id` → `duplicate` (no state change; an applied row still `pending`/`failed` re-schedules its forward — retry-heals); (2) `(fetched_at, attempt)` older than the max over *applied* captures for `(session_id, normalized)` → `stale`, url_record untouched; (3) apply = ledger row + `url_records` + FTS row in ONE SQLite transaction (closes the crash window between "applied" and "recorded"). Ordering keys on BOTH `fetched_at` and `attempt`: `attempt` alone resets to 1 on re-dispatch (not globally monotonic), `fetched_at` alone ties under retry storms. CLOCK ASSUMPTION: all `fetched_at` values are mutually comparable because they come from the single browser-engine writer's clock (holds until the TS capture process inherits the sole-writer role). SQLite path queries/inserts `ingest_captures` directly under the lock (NOT load-all-into-dicts + DELETE-all-reinsert; the ledger is append/update-only); in-memory path uses `self._captures` + `self._latest_applied` dicts. `auth_used` GAP: only the credential-store path sets it true; ambient auth (browser-context cookies, session reuse, auth-wall pages) is invisible → `auth_used=false` there is a known under-report. This layer only guarantees the flag propagates capture → ledger (`auth_used` column) → `/index` document metadata; the decision-37 `auth_used ⇒ local embeddings` gate is a separate work item.
- current stubs/placeholders: tab import jobs are durable status records but do not support cancellation/resume. No automatic index-retry sweeper — a `pending`/`failed` ledger row is retried only on a duplicate receipt (§2.1); the sweeper is deferred to the TS port.
- irrelevant or incomplete code to remove/rework: legacy timestamp usage emits deprecation warnings and can be modernized separately.
- docs that must stay aligned: Backend Core card, Backend API card, and `docs/TESTING.md`.
- local validation commands/checks: `make test-backend`; focused files `tests/unit/test_session_persistence.py`, `tests/unit/test_ingest_v1.py`, and `tests/unit/test_backend_tab_workflows.py`.
