# Backend Core Module Card

- purpose: backend API and local persistence owner for tab workflows and platform accounts.
- product/module functionality: sessions, URL intake, tab import jobs, hybrid search, scrape orchestration, AI clustering/chat proxy, exports, platform auth/B2B/maintainer APIs.
- scope boundaries: owns HTTP contracts under `/api/v1`, backend SQLite persistence, and service-to-service calls; does not own AI provider logic, browser scraping internals, or Streamlit UI state.
- connected modules/submodules: Web UI API client, AI Engine HTTP APIs, Browser Engine scrape/CDP APIs, Ops CLI/MCP tools, Test Harness integration tests.
- allowed change types: route split/refactor, persistence fixes, request/response validation, orchestration error handling, docs/cards, focused tests.
- special operating rules: preserve bearer callback auth, `BACKEND_AGENT_API_TOKEN` on agent tab APIs, Browser Engine control-token forwarding, platform session/API-token behavior, maintainer signup code checks, `/api/v1/*` response shapes, parameterized FTS queries, and underscore import compatibility. Structured logging goes through shared `services/observability.py`: `RequestIDMiddleware` binds/echoes `X-Request-ID`, and every outbound service call sends it via `_ai_engine_request_headers`/`_browser_engine_request_headers` (the pure `_ai_engine_headers`/`_browser_engine_headers` stay auth-only). Never log tokens, credentials, or scraped page bodies (lengths/hashes only). `app/main.py`'s `lifespan` calls `config.config_loader.get_ai_config().validate_config()` and refuses to start on a malformed catalog (finding 27) — Backend Core does not otherwise read this config, but ships and validates the same file AI Engine depends on. `_ai_engine_url()`/`_browser_engine_url()` are the ONLY source of those defaults (`DEFAULT_AI_ENGINE_URL`/`DEFAULT_BROWSER_ENGINE_URL`, finding 32) — never inline a literal `http://ai-engine:8090`/`http://browser-engine:8083` elsewhere. `GET /scrape/status/{id}` must never fabricate `not_started`/`completed` from local URL-store counts when Browser Engine 404s/errors/is unreachable — return `{"status": "unknown", "detail": ...}` instead (finding 28). `POST /chat` proxies to AI Engine `/chat` (mirrors `/cluster`) so `web-ui` never calls AI Engine directly for chat (WI0 B7).
- current stubs/placeholders: backend-to-browser scrape trigger failures are best-effort and need a documented failure contract before behavior changes; tab import cancellation/resume is not implemented.
- irrelevant or incomplete code to remove/rework: broad `app/api/routes.py` should remain a compatibility aggregator while routes move into submodule routers.
- docs that must stay aligned: `docs/MODULE_INDEX.md`, `docs/ARCHITECTURE.md`, `docs/TESTING.md`, `README.md`, submodule cards under `app/*`; when the shared `services/observability.py` contract changes, update all three service Dockerfiles (they copy it) in the same change. `Dockerfile`/`requirements.txt` now also copy `config/` and pin `PyYAML` for `validate_config()` — keep in sync with `config/MODULE.md`.
- local validation commands/checks: `make test-backend`; focused files `tests/unit/test_backend_tab_workflows.py`, `tests/unit/test_scrape_callback.py`, `tests/unit/test_startup_config_validation.py`; then `./scripts/cli.py test --type integration` for API contract changes.
