# Shared Config Module Card

- purpose: shared AI provider and model configuration.
- product/module functionality: provider catalog, per-provider model ROUTES, default models, dimensions, provider capabilities, runtime config loading.
- scope boundaries: owns static config and loader behavior; provider execution belongs in AI Engine providers.
- connected modules/submodules: AI Engine, Ops Tooling init/check-provider/configure-provider, Web UI settings, docs.
- allowed change types: provider catalog updates, default model/dimension fixes, loader validation, tests.
- special operating rules: **every entry under `models:` is one PROVIDER ROUTE, not one model.** The entry key is the exact provider-side wire id (it is written verbatim to `LLM_MODEL`/`EMBEDDING_MODEL` and handed to the adapter unchanged), `provider:` names the one provider that serves it, and `model_family:` is the logical identity shared by every route to the same weights — `gpt-5.6-luna` (codex_cli) and `openai/gpt-5.6-luna` (openrouter) are two routes to one family, as are `bge-m3` (ollama) and `baai/bge-m3` (openrouter). `cost_model` lives ONLY on the provider and is resolved per route by `get_model_cost_model()`; never copy it onto a model entry. `describe_model()`, `get_family_routes()` and `format_model_description()` are how anything shows a model to a human, so a listing can never print a bare name with no provider or price attached. Rejected alternative (2026-08-06), recorded so it is not re-litigated: one merged entry per model with a per-provider id map — it makes the key an abstract name needing translation in every adapter, and pushes `dimensions` into a per-provider sub-map, adding a second way to resolve the wrong vector width (ollama's `qwen3-embedding` is 1024-d, openrouter's `qwen/qwen3-embedding-8b` is 4096-d). **Subscription and metered routes must not be mixed up**: when a family has any route on a `cost_model: subscription` provider, or a route declares `superseded_by:`, that metered route may not be `recommended: true`, a provider `default_models` value, or a `defaults.use_cases` model. It stays REGISTERED (openrouter is the deliberate smoke-test path, `use_cases.smoke_test`) but nothing arrives at it by default. Stated as data in `routing.metered_duplicate_policy` and enforced by `test_no_metered_route_is_defaulted_when_the_family_has_a_subscription_route`, with `test_the_metered_duplicate_set_is_not_empty` as its non-vacuity guard. Keep LLM-only providers separate from embedding-capable providers. **A `supports:` flag may only be set from a call to the endpoint that serves the capability, never inferred from a catalog/model listing.** This is the card's hardest-won rule: on 2026-08-04 `openrouter.supports.embeddings` was set `false` and annotated "verified" on the strength of a scan of `GET /v1/models` (340 entries, no embedding modality); that listing covers only the chat surface and cannot see `POST /v1/embeddings`, which serves embeddings and answered 200 when finally called on 2026-08-05. The false flag propagated to eleven downstream artifacts in a day because each one compared the claim to another copy of it. A listing is weak evidence and must never be recorded as "verified"; if you cannot call the endpoint, say the claim is unverified rather than asserting it (see `deepseek` in `UNRESOLVED_EMBEDDING_CAPABILITY`, `tests/unit/test_provider_routing.py`). Two tests hold this line: `test_embedding_capability_flag_agrees_with_the_adapter_map` (hermetic, every run) and `test_catalog_embedding_claim_matches_the_live_endpoint` (`requires_provider_credentials`, skips without a key). An embedding model entry may also carry `dimensions_configurable: true`, meaning the model accepts a `dimensions` request parameter and emits exactly that width — adapters MUST send it, or the announced width and the real one silently diverge. `validate_config()` (schema-level: providers/models missing required fields or referencing an unknown provider) now runs in every service's FastAPI `lifespan` (backend-core, ai-engine, browser-engine — finding 27), not just ai-engine; backend-core and browser-engine now also copy `config/` and pin `PyYAML` to support this even though they don't otherwise read this config. `ai_models.yaml`'s `ollama.base_url` (`http://localhost:11434`) is the host-process default only — containers always override via `OLLAMA_HOST` (see the comment in the file); keep that comment accurate if the override path changes.
- current stubs/placeholders: local subscription providers may be unavailable at runtime and must remain selectable/reportable. **`gemini_cli`'s four model ids are the weakest claims in this file**: they were read from the installed `@google/gemini-cli` 0.54.0 bundle's own default-model constants, not confirmed by calling anything, because the CLI is unauthenticated on the development host. `-m` passes them straight through, so a rejected id fails at call time with the provider's own error. No `gemini_cli` route to family `gemini-2.5-flash-lite` is registered: catalog keys are globally unique and are wire ids, and the bare id is already the direct-API metered route — both metered `*-flash-lite` routes carry `superseded_by: gemini-3.1-flash-lite` instead.
- irrelevant or incomplete code to remove/rework: `config/models.json` was DEAD DATA and is **deleted** (2026-08-07). `config_loader.py` never opened it and nothing imported it; its contents were a stale Ollama-only model list from `591f6e7`, while `CLAUDE.md` advertised it as part of the catalog "read through config_loader.py" until 2026-08-06. `config/ai_models.yaml` is now the single catalog, with no second file that can drift out of sync behind it.
- docs that must stay aligned: `docs/AI_CONFIG.md`, README environment variables, `.env.example` (`AI_PROVIDER`/`EMBEDDING_PROVIDER` are blank in all three of `.env.example`, `docker-compose.yml` and this catalog — no default anywhere, superseding finding 30's "converge on openrouter" resolution), `docs/SPEC-provider-routing.md` (carries the full record of the 2026-08-05 embedding correction).
- local validation commands/checks: `make test-ai` (incl. `tests/unit/test_provider_routing.py`'s catalog-representation and metered-duplicate tests), `make test-backend`, `make test-browser` (all three now exercise `validate_config()` via `tests/unit/test_startup_config_validation.py`), and `make test-ops`.
