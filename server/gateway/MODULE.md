# TS Gateway Module Card

- purpose: the wk1 edge facade — the server-side gateway that owns browser-origin policy, scoped capability tokens, request identity, and outbound response projection in front of the Python data plane.
- product/module functionality: publishes the `/api/v1/*` surface as an OpenAPI document generated from one declarative route table; enforces the bearer scope each route declares, fail-closed; applies the SEC-45 URL-listing projection; assigns and echoes `X-Request-ID`; proxies everything else byte-for-byte to backend-core.
- scope boundaries: owns POLICY, never DATA. It holds no database, no vector store, no credential store, and no scraper. Python remains the single writer until the wk10 atomic cutover (decision 23), because `services/backend-core/app/sessions/manager.py` loads SQLite into process-local dicts and persists by DELETE-all-then-reinsert — a second concurrent writer silently erases the first (decision 26: Python and TypeScript never write the same SQLite).
- connected modules/submodules: `@tab-organizer/contracts` (the route table it is generated from), Backend Core (its only upstream today), Test Harness (`tests/security` in attached mode), and — from wk2 — the Next.js app package, which calls this gateway server-side.
- allowed change types: adding a route to the table with its scope and, if public, its written reason; adding a projector; origin/token policy fixes; upstream routing. NOT allowed: reimplementing data-plane behavior here, or adding a second writer to SQLite/LanceDB.
- special operating rules:
  - **The facade never attaches a privileged token on behalf of a caller who did not present one.** A caller's own `Authorization` header is forwarded verbatim on scoped routes and omitted entirely on public ones; the upstream re-validates independently. This is the single most important property in `proxy.ts`. Minting a server-side token here rebuilds the exact confused deputy SEC-44 was invented to catch — the two credential-proxy routes that carried no auth dependency while attaching the privileged Browser Engine token themselves.
  - **One route table, two readers.** `packages/contracts/src/routes.ts` generates both the published OpenAPI document and the runtime guard. They cannot disagree, because they are the same fact read twice. A route declared `scope: 'public'` structurally requires a `publicReason`, so an unclassified route is a compile error rather than a probe failure. SEC-44 stays as the black-box proof and should now only fail if the table itself is wrong.
  - **Unconfigured means closed.** A scope whose token env var is unset answers 401, never 200. SEC-21 freezes this but auto-skips in attached mode (it needs harness-controlled env; `SEC_BOOT_*_CMD` is deferred to ~wk8 by decision 42), so `src/auth.test.ts` is currently the only executable check of it against this implementation. Do not delete it when boot mode lands; make it redundant first.
  - **`removeAllContentTypeParsers()` in `app.ts` is load-bearing.** Fastify's built-in `application/json` parser outranks a `'*'` registration. Without that line every JSON body arrives parsed, fails the `Buffer` check in `handleProxied`, and is forwarded as NO body — the upstream then answers "Field required" for a field the caller did send. A silently request-mangling proxy is worse than one that refuses.
  - **Response headers are rebuilt, never copied.** The upstream's CORS headers must not reach the browser (this process owns origin policy) and neither must `Set-Cookie`. Cookies are never forwarded upstream either: there is no cookie-based auth here, and a browser reaching a public route would otherwise have its cookies replayed against the data plane.
  - **Loopback by default.** `GATEWAY_HOST` defaults to `127.0.0.1`, matching the repo-wide invariant that every published port binds loopback. Exposing this to the LAN is a deliberate act, not a fix for a connection problem.
  - **`/openapi.json` is deliberately absent from its own `paths`.** SEC-44 enumerates the route table from that document; listing itself would force it to be either authenticated (unreadable to the probe that must read it) or added to an allowlist reserved for reviewed user-facing exposure. FastAPI excludes it for the same reason.
  - **No secret, token, or URL userinfo in any response body or log line.** `/health` and `/` are unauthenticated by design (SEC-23), and the upstream base URL is never interpolated into an error body because it can carry `http://user:pw@host` under a misconfiguration. The repo's first no-secrets test passed while leaking a credentialed `OLLAMA_HOST` because its canaries were named keys rather than credentials in general.
- current stubs/placeholders:
  - `/api/v1/platform/*` is **not exposed**, and a test asserts its absence. That is plan decision 41 (delete the B2B subsystem by omission at cutover) taking effect — not an oversight to be "fixed" by porting the routes.
  - **Contract disagreement RESOLVED 2026-08-19** (was: probe and service disagreed about `credential_scope_drop`). SEC-45 was widened to six keys and `SECSUITE_VERSION` bumped to 1.7.0; `projections.ts::URL_METADATA_FIELDS`, `routes.py::URL_LIST_METADATA_FIELDS` and the probe now name the same six keys. See the `MODULE_INDEX.md` ledger row and `tests/security/README.md` "New in 1.7.0" for why widening beat narrowing. If a seventh key is ever added to the listing, all three change together or the probe fails — which is the point.
  - No structured request/response logging yet beyond the boot line and `X-Request-ID` propagation. Finding 29 makes real logging a **precondition for the wk10 cutover**, not for wk1, but this is where it lands.
- irrelevant or incomplete code to remove/rework: nothing yet — this module is three commits old. At cutover, `upstream: 'backend'` entries convert to local handlers one at a time and the `proxy.ts` path disappears; the route table and its guards do not.
- docs that must stay aligned: `docs/ARCHITECTURE_PLAN.md` (migration order and decision ledger), `docs/MODULE_INDEX.md` (module tree + boundary rules), `tests/security/README.md` and `tests/security/MODULE.md` (the frozen contract this must keep passing).
- local validation commands/checks:
  - `pnpm typecheck` and `pnpm test` — hermetic, no stack needed (18 cases).
  - Frozen suite, attached mode (decision 43), which is the real acceptance gate:

    ```bash
    docker compose up -d --no-deps backend-core ai-engine browser-engine
    node server/gateway/src/main.ts &          # BACKEND_CORE_URL=http://127.0.0.1:8080
    SEC_BACKEND_URL=http://127.0.0.1:8085 \
    SEC_AI_URL=http://127.0.0.1:8090 \
    SEC_BROWSER_URL=http://127.0.0.1:8083 \
      pytest tests/security -o addopts="" -q
    ```

  - Non-vacuity, re-run whenever this module's policy code changes: set `CORS_ALLOWED_ORIGINS='*'` and confirm SEC-43 `[backend]` **fails**; stop the gateway with backend-core still up and confirm all four SEC-44/45 probes **fail**. A suite that cannot fail against this implementation is not evidence about it.
