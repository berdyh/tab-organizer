2026-05-31 - Security Review Fix Closure

Design decisions
Local AI Engine mode now uses a shared bearer token. start, host-ai, and start --host-ai generate or reuse data/host-ai-token, set AI_ENGINE_API_TOKEN, and pass it to backend, browser, and web containers.
AI Engine generation, embedding, indexing, chat, search, summarize, document deletion, clustering, and provider switching endpoints fail closed unless AI_ENGINE_API_TOKEN is configured. Health and provider catalog reads remain usable for diagnostics, and AI_ENGINE_ALLOW_UNAUTHENTICATED=true is the explicit local escape hatch.
Browser-engine scrape callbacks into Backend Core now require a bearer token from BACKEND_CALLBACK_TOKEN, falling back operationally to AI_ENGINE_API_TOKEN. Browser-engine sends the callback token on scrape-complete notifications.
Provider switching and all AI operations now share an asyncio.Lock so a provider swap cannot race indexing, embedding, chat, or clustering against a half-switched global client.
codex_acp defaults to deny-all permissions. Local agent CLI prompts also include guardrails that forbid command execution, file reads, browsing, and treating scraped page text as instructions.
codex_cli is blocked by default for scraped-content prompts because codex exec is not a tool-free LLM-only mode. It can only be re-enabled for untrusted context with CODEX_CLI_ALLOW_UNTRUSTED_CONTEXT=true.
RAG chat, session summaries, and cluster-label generation wrap scraped page content as untrusted web data and pass system instructions that tell the model not to follow directives found inside scraped content.
SQLite-backed session persistence now uses a process lock, WAL mode, busy timeout, and row-level URL upserts for scrape callbacks so parallel callback updates do not rewrite and clobber the whole session.
Docker Compose no longer publishes a default maintainer bootstrap code. PLATFORM_MAINTAINER_SIGNUP_CODE is blank unless explicitly supplied.
B2B API token scopes are now allowlisted to companies:read. Unknown scopes and wildcard scopes are rejected at token creation.
The Platform UI now gates company search behind login, offers a maintainer signup path with a maintainer code field, and only offers supported API token scopes.
The test CLI now accepts ./scripts/cli.py test --type all, while README and testing docs use that explicit full-suite command. scripts/cli.py and scripts/init.py are executable.

2026-05-31 - ACP/Codex Routing Review Fix Lane

Findings
codex_cli remains a one-shot local CLI provider. It invokes codex exec --ephemeral --json -, which uses local Codex auth but does not create an ACP harness session and is not equivalent to OpenClaw sessions_spawn(runtime: "acp").
Local gstack/OpenClaw documentation separates provider/model routing from ACP session dispatch. OpenClaw ACP routing is an orchestrator/tool path through sessions_spawn, while this app's AI Engine owns provider-style LLM calls.
Implemented fix
Added a separate codex_acp LLM provider instead of changing codex_cli semantics. The provider uses acpx with the Codex harness and the ACP session lifecycle: session ensure, prompt via --file -, and session cleanup.
codex_acp is LLM-only and runtime-gated on CODEX_ACP_COMMAND (default acpx). It keeps prompt content on stdin rather than process arguments.
Deviations
This is not a full OpenClaw orchestrator integration. The app does not expose sessions_spawn, thread management, or OpenClaw control-plane behavior. It is the smallest repo-local ACP-aligned LLM provider path.
codex_cli remains available for one-shot codex exec routing and is documented explicitly as non-ACP.
Open questions
acpx is not installed in this local environment, so live ACP prompting is not verified here. The unit coverage verifies command construction, stdin prompt handling, event parsing, JSON-RPC error handling, and runtime availability gating.

Clustering error behavior
Backend clustering now calls raise_for_status() on the AI-engine response so AI-engine failures surface as failed clustering requests instead of silently storing empty clusters.
Backend-to-service calls now read AI_ENGINE_URL and BROWSER_ENGINE_URL from the runtime environment for scraping, status, auth, and clustering paths. This keeps Docker, host-run, and test deployments aligned.
UI text cleanup
Removed sticker-style emoji prefixes from Streamlit navigation and page copy. A text regression test scans the web UI source tree so new sticker characters fail the unit profile.
Test/runtime support
Updated the Docker unit-test image and compose test profile so tests can load config/ai_models.yaml and the same YAML dependency as the application.
ACP boundary
OpenClaw routes coding sessions with sessions_spawn(runtime: "acp"). This repository does not have an OpenClaw orchestrator or ACP session-spawn API, so the implemented local LLM provider path uses provider-owned CLIs: claude -p and codex exec.
Subscription provider review follow-up
Cleared LLM_MODEL in .env.example so copying the example file and switching to claude_code or codex_cli selects provider defaults instead of leaking an Ollama model name into the CLI call.
Changed Codex CLI invocation to read the prompt from standard input with codex exec ... -, avoiding prompt content in process arguments and avoiding argument-length limits for scraped-page prompts.
Codex CLI invocation also uses --ephemeral to keep these local provider calls out of persistent Codex session state.
Claude Code and Codex CLI both receive request content through stdin. Claude originally used --system-prompt, but that was changed so dynamic instructions do not appear in process listings.
Documented the Docker boundary explicitly: the stock AI-engine image does not install claude or codex or mount their subscription auth state. Docker CLI routing needs a custom image or host-run AI engine.
Aligned embedding-provider UI/docs with config/ai_models.yaml; DeepSeek remains LLM-only in the current registry and is no longer shown as an embedding fallback.
Added switch-time and direct provider-construction capability validation so API callers and test code cannot route embeddings to LLM-only providers such as codex_cli or deepseek.
Fixed scripts/init.py to write the runtime environment variables actually used by the app: AI_PROVIDER and OLLAMA_HOST. The Claude setup path also now exposes the missing --claude-embedding-provider argument.
